## Decisioni architetturali prese e perché

1. **Frontend su Azure Static Web Apps (Free) invece che nello stesso App Service dell'API**: hosting pensato per SPA, HTTPS e CDN gratuiti, fallback SPA integrato, FE e BE disaccoppiati (al costo di dover configurare CORS).
2. **Deploy del frontend con GitHub Actions** (non SWA CLI da locale): CI/CD automatico a ogni push su `main`, valore aggiunto per il portfolio. **Deployment authorization policy = GitHub**, così non c'è nessun deployment token da gestire a mano.
3. **`environment.ts` = produzione, `environment.development.ts` = locale** (convenzione Angular recente): la build di default punta a Azure, lo sviluppo locale resta invariato.
4. **CORS controllato da variabile d'ambiente** `Cors__AllowedOrigins__0` sull'App Service (già leggibile dal codice dalla sessione precedente): l'origin di produzione si aggiunge dal Portale senza ricompilare.
5. **Nessun dato da migrare tra i due account**: il DB era vuoto e l'app applica le migration all'avvio (`Database.Migrate()`), quindi la migrazione è stata "ricrea le risorse", non "sposta i dati".
6. **Non committare né pushare in autonomia**: comandi Git eseguiti da Luca; Claude ha fatto solo dry-run (`git add -n`) e scansione di possibili segreti prima del primo commit (nessun segreto trovato; `.claude/`, `CLAUDE.md`, `log/` inclusi nel repo per scelta di Luca).

## Problemi risolti

1. **`RequestDisallowedByAzure` — "region not accepting new customers"** su West Europe, sia per la Web App sia per la Static Web App: il nuovo account non può creare risorse lì. Risolto scegliendo un'altra regione (Sweden Central per App Service/SQL; per la SWA una regione non europea, dato che le SWA supportano poche regioni e per file statici serviti da CDN la scelta non incide sulla latenza).
2. **`ExternalAdministratorLoginSameAsSqlAdmin`** creando il SQL Server: il login admin SQL non può coincidere con l'admin Microsoft Entra. Risolto scegliendo un nome diverso (es. `teamcraftadmin`).
3. **Box grigi/non modificabili** su Connection strings: la casella nella pagina SQL Database è di sola lettura, si copia e si modifica altrove (poi va incollata come app setting `ConnectionStrings__DefaultConnection` sull'App Service).
4. **CORS apparentemente ancora attivo dopo la configurazione**: verificato con `curl` che l'API rispondeva correttamente (`Access-Control-Allow-Origin` uguale all'origin della SWA, GET 200 su tutti gli endpoint principali, preflight 204) e che il bundle della SWA puntava al nuovo URL API. Il problema era una cache del browser; risolto con ricarica forzata/finestra in incognito.

## Problemi/punti ancora aperti

1. **Risorse del vecchio account Azure ancora da cancellare** (Resource Group, SQL, App Service): se in Free Trial consumano credito inutilmente.
2. **Il profilo di publish di Visual Studio** del vecchio account può essere ancora presente in `Properties/PublishProfiles` del progetto API e potrebbe contenere riferimenti (ID risorse/subscription) al vecchio account; verificare se è stato committato.
3. **Pipeline CI/CD solo per il frontend**: il backend si pubblica ancora a mano da Visual Studio → Publish.
4. **Autenticazione JWT** ancora non implementata.
5. **Budget bundle Angular**: la build di produzione segnala un warning sul budget iniziale (700 kB contro soglia 500 kB, limite d'errore 1 MB) — non bloccante ma da tenere d'occhio.
6. **`.NET 8` LTS termina il supporto a novembre 2026**: pianificare l'upgrade (probabilmente .NET 10).
7. **`src/ai_output_audit.md`** dice ancora "Stack: .NET 7" (documento storico, non aggiornato) e nel repo esiste ancora la cartella residua `src/backend/TeamCraft/TeamCraft.API/` (vecchio scaffold non referenziato dalla `.sln`).
8. **README**: la frase sulla porta locale per `apiUrl` è generica (ci sono 3 profili di avvio in `launchSettings.json`); da precisare quando si sa quale profilo si usa.
